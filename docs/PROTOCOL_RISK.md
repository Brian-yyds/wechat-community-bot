## 当前自报（第一阶段）

- 协议类型：`mock`（本地模拟，`MockAdapter`）
- 配置项：`wechat.protocol = mock`，`wechat.protocol_type = mock`
- 框架或库名称与版本：无真实微信协议依赖；运行时只用 Python 标准库（可选 pyyaml）
- 登录态：无。消息由脚本、文件或标准输入注入，发送只记录在内存，不触达微信
- 已知检测与封号风险：
  - 当前不登录任何微信账号，因此没有真实封号路径
  - 若后续改为 Hook / Web / iPad / Windows / Mac 等非官方通道，将面临易被检测、限制登录设备、频繁二次验证，以及可能违反使用条款等风险；届时必须更新本文件「实际采用」一段，而不是沿用 Mock 自报
- 已具备、且与协议无关的降低风险措施：
  - 单群与全局发送频率上限，公告与自动回复分开配额
  - 拟人延迟默认 2–6 秒（下限不得低于 1.5 秒）
  - 夜间静默默认开启（00:30–07:00，Asia/Shanghai）：不主动发公告（可暂存），自动回复默认丢弃、不排队补发
  - 定时公告默认抖动 ≤3 秒，保证落在准点 ±5 秒内
  - 同内容冷却，避免重复刷屏
- 未采用的协议：Hook、Web、iPad、Windows/Mac、任何官方或第三方登录框架（第一阶段均未接入）
- 日期：2026-11-11
