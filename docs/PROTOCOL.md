# 微信协议说明（自报）

完整模板与当前 Mock 自报见 [PROTOCOL_RISK.md](PROTOCOL_RISK.md)。

第一阶段**尚未接入任何真实微信协议**。当前运行时使用本地 `MockAdapter`（`wechat.protocol = mock` / `protocol_type = mock`），只在本机注入和记录消息，不登录微信，也不接触 Hook、Web、iPad、Windows 或 Mac 客户端。

## 计划中的可选协议与主要风险（尚未采用）

后续若接入真实协议，必须在本文件更新「实际采用」一栏，并继续把所有发送走限速与拟人发送层。下面只做风险知情说明，不是实施指南。

| 类型 | 典型来源 | 已知风险（摘要） |
| --- | --- | --- |
| Hook / 注入 | 在已登录的手机或 PC 客户端注入 | 违反客户端使用条款，检测与封号概率高，版本一变即失效，还可能带来设备安全风险。 |
| Web / 网页版协议 | 模拟网页微信或其他网页通道 | 官方网页能力已收缩，会话容易失效，批量群发同样容易被限制。 |
| iPad / Pad 协议 | 模拟平板登录 | 属于非官方登录态，账号风控敏感，掉线与二次验证常见。 |
| Windows / Mac 协议 | 模拟桌面客户端 | 与 Hook 类似，属于非官方通道，稳定性与封号风险都高。 |

**本阶段明确采用：`mock`（本地模拟）。** 因此现阶段封号风险来自「尚未接入真实协议」，而不是某一种 Hook/Web/iPad 实现。待调研文档 `PLAN.md` 给出推荐方案后，再在本文件改为实际协议名称，并评估限速、夜间静默与拟人延迟是否需要加严。

## 降低封号风险的产品侧措施（与协议无关，第一阶段已具备）

- 单群与全局发送频率上限；
- 发送前随机延迟（默认 2～6 秒）；
- 可选「正在输入」钩子；
- 夜间静默（默认 00:30–07:00，不主动发公告）；
- 自动回复与定时公告分开配额；
- 同内容冷却，避免重复刷屏。

严禁把本仓库用于博彩、六合彩、下注、结算、收款等被禁止的业务。

## 可选读取通道（适配器 A，默认未启用）

当配置 `wechat.inbound = local_capture` 时，读取侧改为「用户提供的已解密 / 明文 SQLite 只读增量抓取」，不注入、不 Hook、不内置密钥提取。默认演示仍是 `mock`。启用前必须阅读 `docs/ADAPTER_A.md` 与下面的风险说明：该路径违反《微信个人账号使用规范》，且已有 `wx-cli` 当天被提示「非官方客户端/外挂」并封号、以及 2026-01 GitHub DMCA 下架解密类仓库等案例。用户须使用专用小号并接受残余封号与合规风险。
