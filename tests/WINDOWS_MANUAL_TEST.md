# 用户 Windows 人工实测清单

真实微信只能在**用户 Windows 电脑**上运行。本清单配合自动化用例（`tests/`）使用，用于专用小号的分阶段实测与 7–14 天观察记录。

**主路线：** 官方 PC 微信 + 本地库增量只读 + UIA 限频发送；C 通知辅助、D OCR 降级。不做 Hook、不做非官方协议号。

**重要边界：**

- 必须使用**可丢弃的专用小号**，不要用主号或支付号。
- 用户已接受封号风险。本清单只记录限频是否遵守、以及是否出现风控信号，**不承诺「必不封号」「一周必不封」「观察期满即可视为安全」**。
- 延迟目标是观察用的分段分位数，不是「必须 2 秒内发出」的口号：规则回复且会话已打开，P95 目标约 3 秒；其余场景 P95 目标约 8 秒。阈值可配，见 `ACCEPTANCE.md` C 节。
- 严禁博彩、六合彩、结算、收款等功能；发现立即停止并报告智哥。

## 2. 安装与运行（占位，以开发文档为准）

具体命令、依赖和目录以开发交付的 README 或 `docs/WINDOWS.md` 为准，不要照抄过期示例。建议按下面勾选：

1. [ ] 已阅读开发 README / `docs/WINDOWS.md`。
2. [ ] 已安装官方 PC 微信，并用**小号**扫码登录（记录登录设备名称）。
3. [ ] 已按文档安装运行时依赖（占位：`python -m venv .venv` 与 `pip install -r requirements.txt`，以开发文档为准）。
4. [ ] 已复制并修改配置（占位：`config/example.yaml` → 本地配置；确认 `wechat.inbound` / `wechat.outbound` 与主路线一致）。
5. [ ] 运行模式先设为 **`observe`**（只收不发）。
6. [ ] 启动命令以开发文档为准（占位：`python -m src.main --config <你的配置>`）。
7. [ ] 一键自检（若有）已通过（占位：`python scripts/selfcheck.py`）。
8. [ ] 确认日志已脱敏，日志里看不到完整手机号、wxid、token。

出现安装报错，把完整版本号、报错原文和配置（脱敏后）记入观察表，不要反复重启微信或反复扫码。

## 3. 小号分阶段测试步骤

原则：**先只读，再公告，最后才自动回复**。每一阶段至少稳定观察一段时间，再进入下一阶段。任何风控信号立即停止发送（见第 5 节）。

### 3.1 空群 / 测试群（只读）

1. 建一个只有小号和测试号的空群，或使用可丢弃的小群。
2. 运行模式：`observe`。
3. 测试号在群里发：提问、闲聊、广告样例（不要涉及真实资金）、一条「收到」。
4. 小号停留在**其他会话**，对该测试群设置**免打扰**，再各发一轮。
5. 核对本地整理结果：上述消息都应被抓到（图/语音可只记占位，但要有这条消息）。漏抓记入观察表。
6. 确认此阶段**没有任何群消息被机器人发出**。

### 3.2 小群（只读 → 公告 → 回复）

1. 仍先 `observe`，确认免打扰 / 折叠 / 未打开该群时也不漏消息。
2. 切换到 `announce`：到点观察一条预告模板公告（文案须先人工确认）。核对准点大约在 ±5 秒内；不要在夜间静默窗口强行补发刷屏。
3. 确认提问不会被自动回复。
4. 再切换到 `reply`：对「开户/手续费」类流程提问应回复一次；广告、禁止类、自己的消息、其他机器人消息不应回复。
5. 连续触发时核对冷却、小时上限（默认 40）和拟人停顿，不应整点机械连发。
6. 模式切换后**下一动作**即按新模式；重启程序后模式应保持。

### 3.3 真实交易会员群（最后才进）

1. 先以 `observe` 接入真实群，至少观察数日，确认漏抓、掉线、风控提示可接受，再考虑 `announce` / `reply`。
2. 真实群里不要做高压测、不要对广告互动、不要给出买卖建议。
3. 会话已打开的规则回复，用秒表或日志分段看：检出 / 决策 / 发送是否大致落在 3 秒 P95 目标附近；未打开会话或需切窗时看 8 秒目标。这两项是观察目标，允许按配置调整，不要改成「必须 2 秒内」。

## 4. 每方案的人工验证项

| 方案 | 角色 | 要看什么 | 通过观察 |
| --- | --- | --- | --- |
| A 本地库只读 | 主读取 | 当前未打开、免打扰、折叠的群，只要 PC 客户端已同步，文本消息应被增量抓到；游标在微信重启后续读 | 漏抓 0（已同步前提下）；重启后不丢不重 |
| B UIA 发送 | 主发送 | 限频、拟人停顿、失败可感知（找不到窗口、超时、锁屏） | 不硬闯上限；失败能停并记日志，不疯狂重试 |
| C 通知辅助 | 仅唤醒 | 有通知时可提示；正在查看的会话、免打扰可能没有通知 | **不能**把「没通知」当成「没消息」；不能当全量真源 |
| D OCR 降级 | 仅降级发送 | 低置信度应降级或放弃，并留下降级标记 | 不把 OCR 当采集主干；延迟往往更长，按 8 秒目标观察 |

组合应为：默认 A 读 + B 发；C/D 可关可开，但不得单独承担全量抓取。

## 5. 风险信号与立即停止条件

出现下列任一情况，**立即停止发送**（切到 `observe` 或退出进程），不要自动反复扫码、不要打码过验证、不要换号硬闯：

- 账号被踢下线、频繁掉线
- 出现「环境异常」「使用非官方客户端 / 外挂」等提示
- 要求短信、扫码、人脸等异常验证
- 限制登录电脑端、限制发消息
- 发送失败率突然升高，或好友/群功能被限制
- 发现博彩、结算、收款类功能或相关回复

停止后把时间、截图说明（不要包含验证码或完整账号）和当时模式记入观察表，并通知智哥 / 核查。只读是否继续，由用户决定；默认建议连读取也先停，观察账号是否进一步被限制。

## 7. 结束后的评估准则

可以进入下一阶段（例如由只读改为公告，或由公告改为自动回复）的**最低观察结论**（仍不保证不封）：

- 没有出现第 5 节的立即停止信号
- 在客户端已同步的前提下，文本消息漏抓为 0，或漏抓已定位且有对策
- 重启微信与重启程序后，游标续读不丢、不重
- `observe` / `announce` / `reply` 行为与切换符合验收清单 M 节
- 发送次数遵守小时上限与夜间静默；没有回复风暴、没有回自己或广告
- 延迟分段记录可核对，打开会话的规则回复大致落在 3 秒目标附近，其余场景落在 8 秒目标附近（按实际配置）
- 日志无完整手机号、wxid、token

若观察期内出现风控提示或限制登录：即便漏抓为 0，也判定**不应继续加开发送**，先停并评估是否弃用该小号。
